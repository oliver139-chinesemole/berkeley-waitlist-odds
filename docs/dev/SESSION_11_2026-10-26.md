3. The status line did not compare terms on `main`; "the status line already does this" in plan 1.4 was wrong. #42 adds `BWO.isForecastTerm`.
4. "Every run for a month has written zero rows" was wrong: 337 of the 1,010 October deltas carried 7,379 post-deadline rows; the true statement is "no Spring 2027 row, most Fall runs write 0".
5. I5, I6 and I8 were already live on the insights page; only I7 is open.

7. The budget capacity is about 2,468 pages at the last Fall run's rate, not the plan's 2,370 (an older 1.72 pages/s).
8. The review's "nine excluded lecture sections" named eight; PLANTBI 101L LEC 101 is the ninth. The "239 Fall entries" are 149 DIS, 62 LAB, 25 STD and 3 LEC, not 236.
9. `complete` is never true on a scheduled run (priority scope), so it is not a pass signal for the switch.
10. `gh variable set SCRAPE_TERM` alone flips the chain; the manual dispatch only saves the wait.
11. A course-code deep link was never broken by the Lookup re-render (it resolves before `status.json` returns); a title deep link was.
12. #46's swap step aborted the whole run on an empty cohort (`EVENTS=$(python -c ...)` under `bash -e` with no candidate file); fixed in #50.

15. PR numbers 34 to 41 are monitor issues, not PRs.
